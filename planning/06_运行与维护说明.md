# 运行与维护说明

分享仓库的安装、文献库快照使用教程见根目录 [README](../README.md)；协作开发、测试、快照更新和技能重新打包见 [开发接手指南](../DEVELOPMENT.md)。本页下列个人绝对路径仅表示原维护者本机位置，其他开发者使用自己的库路径。

## 运行
- 双击 `start.bat`，或在项目目录执行：`.venv\Scripts\python.exe -m litmgr`
- Windows 可运行 `.venv\Scripts\python.exe scripts\create_shortcut.py`，生成带图标的“文献管理系统”启动快捷方式。移动项目目录后需重新生成，该本机快捷方式不提交 Git。
- 首次启动会让你选择“文献库文件夹”（PDF、翻译、数据库都存放在里面，复制整个文件夹即可备份/迁移）。
- 命令行指定文献库：`python -m litmgr --library D:\我的文献库`

## 环境
- Python 3.12 + 项目内虚拟环境 `.venv`（依赖见 `requirements.txt`）。
- PySide6 固定为 6.8.3：6.12 在本机上 DLL 加载失败（Qt 与 miniforge 的 VC 运行库不匹配），6.8.3 已验证可用。
- 环境自检：`.venv\Scripts\python.exe scripts\check_env.py`

## 测试
- 单元与界面冒烟：`.venv\Scripts\python.exe -m pytest`
- Windows 离屏测试请先在 PowerShell 设置 `$env:QT_QPA_PLATFORM='offscreen'`、`$env:QT_QPA_FONTDIR='C:/Windows/Fonts'`、`$env:QTWEBENGINE_CHROMIUM_FLAGS='--no-sandbox --disable-gpu'`，再运行 `.venv\Scripts\python.exe -m pytest -q`。字体目录必须提供，否则离屏平台可能没有字体，界面文字变成方框，测试生成的 PDF 也可能没有可搜索文字。
- 截图式界面检查（离屏渲染，输出到 `scripts/_shots/`）：`.venv\Scripts\python.exe scripts\ui_smoke.py`

- 性能剖析（在文献库**副本**上量各操作耗时，不改原库）：`.venv\Scripts\python.exe scripts\profile_ui.py <副本路径> [--cprofile] [--prewarm]`
- 静态检查（未用的导入、未定义的名字）：`.venv\Scripts\python.exe -m pyflakes litmgr tests`

## 日常数据位置
- 配置与日志：`%APPDATA%\litmgr\`（`config.json`、`litmgr.log`）。`config.json` 里的 `ui_state` 保存主窗口位置与分栏；阅读窗口的状态保存在数据库的阅读历史里。
- 数据库：`<文献库>\db\litmgr.db`；自动备份：`<文献库>\backups\`
- **原维护者的日常文献库**位于 `D:\2file\研究生2026.9.7\文献库`，与代码分开，日常编辑不会自动提交；本仓库额外提供 `shared_library/` 分享快照，明确纳入 Git 的主数据库、6 份已有备份及 PDF/翻译/卡片与原库独立。

## 缓存与预热（性能相关，不影响数据）
- 翻译 md 渲染出的 HTML 按内容哈希缓存在系统临时目录 `litmgr_view\page_*.html`，最多保留 40 个，可随时删除。
- 程序启动约 1~2 秒后会在后台预热阅读器（导入 QtWebEngine 等），所以首次点“阅读”几乎不用等；退出时自动释放。
- 检索（`SearchService.run`）只读取列表实际显示的列、过滤条件和排序用到的字段；需要完整字段值请用 `papers.get`。

## 应用图标

- 可编辑源图：`litmgr/assets/app-icon.svg`；主 PNG：`app-icon.png`；Windows 多尺寸图标：`app-icon.ico`。
- 修改 SVG 后运行 `.venv\Scripts\python.exe scripts\build_icon.py` 重建成品，预览在 `planning/assets/app-icon-preview.png`，包含浅/深背景及小尺寸效果。
- `ui.app_icon.configure_app_icon()` 在应用启动、创建业务窗口前设置全局图标和 Windows AppUserModelID；所有窗口继承应用图标。修改后重启软件生效。

## 版本管理（git）
- 代码文件夹已初始化为 git 仓库，每个重构批次一次提交，可用 `git log` 查看、`git checkout <提交>` 回退。
- 日常文献数据的备份靠程序内“备份与恢复”（数据库快照）或复制整个库文件夹；Git 中的 `shared_library/` 是主动交接的数据版本，不自动同步个人库。

## 扩展指南（如何增删功能）
- 新字段类型：`core/field_types.py` 增加类型并注册（需要特殊的过滤规则就覆盖 `matches`）；`ui/field_widgets.py` 增加控件并 `EDITORS.register`。
- 新批量操作：在 `ui/paper_actions.py` 加方法并在 `build_row_menu` 加一行菜单项。
- 新过滤维度：`core/query.py` 的 `SearchQuery` 加字段，`services/search_service.py` 的 `run()` 加一步。
- 新导出格式：`services/export_service.py` 中 `exporters.register(名字, 函数)`。
- 新窗口：写窗口类（带 `closed` 信号），在 `ui/window_manager.py` 增加 `open_xxx`。
- 新数据表：在 `storage/migrations/` 新增 `NNNN_说明.sql`，再加对应仓库与服务。
- 插件：在 `plugins/` 下新建包，约定 `register(ctx, windows)`；在 `__main__.py` 的扩展点加载。

## 字段分组管理

- 入口：主窗口“字段管理…” → “管理分组…”，可新建、重命名、删除“概要”“基本信息”等字段分组。
- 新建空分组后会独立保存，重启后仍能选择；详情表单只显示包含未归档字段的分组。
- “字段管理”的“字段分组”下拉框可筛选组内字段；此时“新增字段”默认归入选中的分组。编辑已有字段的“分组”可移动字段，选择“未分组”可取消归属，也可直接输入新的组名。
- 重命名同步更新全部组内字段（含已归档字段）；删除分组会把这些字段移到“未分组”，保留字段编号、顺序、内容和归档状态。
- 需要调整字段的全局顺序时，先切到“全部分组”再拖动；筛选期间禁用拖动，以免改变其他组的顺序。
- 首次用新版本启动时会自动执行迁移 0004，并在升级前保存数据库快照；原有分组、字段和论文内容会保留。已打开的旧程序需关闭后重新启动才能使用新入口。

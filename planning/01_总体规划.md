# 文献管理系统 - 总体规划

> 目标用户：北京师范大学人工智能学院研一，方向为教育文档版面分析。
> 定位：长期使用、单机、离线、可持续扩展的个人文献管理系统。

## 1. 已确认的决策

- 技术栈：Python 3.12 + PySide6（界面、多窗口、QtPdf 查看 PDF、QtWebEngine 渲染 Markdown 与 LaTeX 公式）+ SQLite（FTS5 全文检索）。
- 数据以数据库为准：txt 卡片只是导入入口，可导出回 txt。
- 字段类型：单行文本、长文本、单选、多标签、数字、日期、星级、链接。
- 一篇论文可挂多个 PDF（正文、补充材料、附录），并支持通用“附件”（如 docx 详细内容）。
- 导入时文件复制进统一“文献库文件夹”，整个文件夹可直接备份。
- 旧格式卡片通过“导入向导”处理，识别不了的内容进“待归类内容”，再一键映射。
- 开发节奏：先做核心版，再逐步加功能。全程不联网。

## 2. 对真实文件的观察

- 模板为 `字段名：内容`，25 个字段，内容可跨多行 -> 解析以“行首出现已知字段名/别名”为分隔。
- 字段会演变（如“当前发表状态”“当前PDF版本”），同一字段有不同写法（“首次公开日期”/“首次发布日期”）-> 字段别名 + 未知字段。
- 旧卡片有 `(1)中文标题：` 编号格式 -> 解析器忽略编号前缀。
- 文件名规律：`{标题}{arXiv号}论文卡片.txt` / `…翻译.md` / `…补充材料.pdf` -> 自动配对。
- 翻译 md 含大量 `$$` 公式 -> 本地 KaTeX 渲染。

## 3. 架构

严格单向依赖：`ui -> services -> storage -> core`。界面层不直接访问 SQL。

- `litmgr/core`：领域模型、事件总线、注册表、异常、配置。
- `litmgr/storage`：SQLite 连接、迁移、仓库、文献库文件系统。
- `litmgr/importers`：卡片解析器、文件配对器。
- `litmgr/services`：业务服务（论文、字段、检索、导入、导出、备份、对比、标签分组、笔记）。
- `litmgr/ui`：全部界面。
- `litmgr/plugins`：以后新增的功能模块。

低耦合手段：事件总线（修改后各窗口自动刷新）、注册表（字段类型/导出器/详情面板可插拔）、窗口管理器（统一管理多窗口）。

# 全文翻译规则

本规则来自用户的《论文翻译提示词1.md》。只替换原提示词中“聊天内一个代码块输出、用户逐次复制、回复末尾下次继续”的交付方式，改为直接写文件和内部续作登记；其余翻译质量要求保留。

用户补充要求：译文和卡片不得编造，事实必须能在所提供 PDF、补充材料或已核实的可靠网络来源中找到依据。联网核实流程见 SKILL.md“事实核实与禁止编造”；网络补充用于有来源标注的卡片事实，不混入原文翻译。

## 忠实与覆盖

- 用正式、准确、自然的中文学术语言，保持原表达、顺序与段落；不口语化、不总结替代、不删减、不扩写、不额外解释。原文错误或前后矛盾照译，必要时标“[原文如此]”，不能根据常识擅自改正。
- 不凭记忆修补原文缺失的数字、符号、参考文献或方法步骤；看不清就回看对应页，仍未核实则如实记录位置，不用合理猜测冒充译文。对作者报告的结果保持原文语气，不升级成独立验证结论。
- 处理全部英文文字：题名、摘要、关键词、正文、各级标题、图题图注、表题表头单元格与注释、脚注、附录、数据/指标说明、作者贡献、通讯作者、出版/投稿/版权许可说明、CCS 概念、致谢、参考文献等。作者名保留原文；机构给中文并保留英文。
- 图片本体、流程图、示意图不重新生成，不要求翻译图片内部嵌入文字；在原位置保留编号并忠实翻译完整图题图注及正文说明。只有图题就只译图题，不补写图意。
- 页眉页脚里独有的正文信息不能漏；纯粹重复的页码/题名不用每页重抄。正文 PDF 内的所有附录仍属正文文件的翻译范围，独立补充材料另接在同一 Markdown 后。
- 分段写入时保留句子、脚注、表格等边界锚点；不能用“其余略”“参考文献略”“同上”等替代源文。

## Markdown 与公式

- 真正写出 UTF-8 Markdown 源文件，不在整个文件外套三反引号；原文代码/算法需要围栏时可正常使用。正常段落间空行，不把每个句子强制断成独立段。
- 用标准 `#` 到 `######` 标题，保持论文节层级；合并文件的章节偏移按 SKILL.md 的外层结构处理。
- 行内数学统一 `$...$`，独立公式统一 `$$` 换行公式换行 `$$`；保留原编号 `\tag{3}`。不要使用 `\(...\)`、`\[...\]` 或 HTML 数学公式。
- 上下标、求和、积分、矩阵、集合、希腊字母等使用原始标准 LaTeX。不能同时输出渲染后的 Unicode 数学式和 LaTeX，也不能在公式外复制一份文本公式。
- 公式提取乱码时必须查看原 PDF 页面恢复，不能复制乱码或臆造缺失项。特别核对负号、上下标、粗体向量、分数、求和范围和公式号。
- 表格完整转为 Markdown，保留所有行列、数值、单位、粗体/最优结果含义及表下注。可读的普通英文表头/文字译成中文；模型、数据集、缩写保留英文。宽表不删列；合并单元格可展开并显式重复所属表头，不能丢归属。无法识别的关键内容列为待解决问题，不发布已完成成品。

## 术语与标识

- 首次出现的专业术语采用“中文（English Original，缩写）”，后续按习惯用缩写，维护段落间和正文/补充材料间一致性。
- 模型正式名称保留原英文，如 DocLayout-YOLO、PP-DocLayout、LayoutLMv3、DeepSeek-OCR、MinerU2.5；有英文全称时保留并给译名，不自行改造模型名。
- 数据集、算法、机构、会议/期刊、项目等名称保留英文以便检索；技术术语有通行中文译法时翻译并保留首处英文。
- DOI、URL、邮箱、arXiv 编号逐字保留，不翻译、不擅自补全。

## 引用与参考文献

- 保留正文引用编号及范围，如 `[35, 57, 156]`、`[130–132, 176]`；不改脚注、不删除、不重新编号。
- 每条参考文献完整保留作者英文、原题名，并给中文译名；会议/期刊保留官方英文并给中文名称或说明。年份、卷期、页码、DOI、arXiv、URL 不丢失；模型/数据集/项目名保留英文。
- 参考文献译名不是卡片的扩展阅读推荐，不添加源文没有的条目。补充材料的参考文献即使与正文重复也按原文件保留。
